# Project Charter
## HolcemLK Banker — Customer Signature & Image Collection System

| Field | Detail |
|---|---|
| Project Name | HolcemLK Banker Customer Signature & Image Collection System |
| Sponsor | Bank Management / IT Head |
| Project Manager | *(to assign)* |
| Environment | Local network only, on-premise, single host PC for backend + both DBs |

### 1. Purpose
Digitize the capture and secure storage of core-banking customers' signatures and profile images, replacing manual/paper-based collection, while enforcing strict access control so images can only be captured under an Admin-authorized, time-bound session.

### 2. Objectives
- Securely capture and store customer signature/photo images linked to `CustomerID` in the existing `customerinformation` table.
- Enforce that image capture can only happen after a Bank Officer scans a valid, one-time QR session token generated by an Admin.
- Maintain a full audit trail of who captured/replaced each image and when.
- Keep customer PII and image data logically and physically separated across two databases.
- Operate entirely on an isolated local network with no internet exposure.

### 3. Scope
**In scope:** Node.js backend (dual DB), QR Generator App (Admin, Flutter), Collector App (Bank Officer, Flutter), image encryption/watermarking, authentication/authorization layer, audit logging.

**Out of scope:** Changes to `customerinformation` or `systemusers` table schemas, core banking transaction processing, internet-facing access, public app-store distribution.

### 4. Stakeholders
- **Sponsor:** Bank management
- **Project Manager:** Coordinates delivery
- **Business Analyst:** Confirms officer workflow requirements
- **System Architect / Backend Developer:** Node.js, DB, security design
- **Flutter Developer:** QR Generator App, Collector App
- **QA Engineer:** Security + functional testing
- **Bank Admin (end user):** QR generation
- **Bank Officer (end user):** Image/signature collection
- **Compliance Officer:** PDPA / biometric data handling sign-off

### 5. Success Criteria
- Zero unauthorized image capture (no capture possible without valid QR session).
- Password/auth security passes independent review (bcrypt/argon2, no plaintext, no reversible encryption in login path).
- All images encrypted at rest; audit trail complete for 100% of capture/replace events.
- System functions fully offline/LAN-only with no external dependency.

### 6. Assumptions
- Local network infrastructure (router, switches) is controlled by the bank's IT.
- `systemusers` / `customerinformation` schemas will not change during this project.
- Devices used for Collector/QR apps are bank-owned or bank-approved.

### 7. Constraints
- `customerinformation` and `systemusers` table structures are fixed.
- Entire system must run on a single local PC (no cloud infra).
- Must operate within existing WiFi router / LAN topology.

### 8. High-Level Risks
MITM on LAN, QR token replay, credential compromise, image data leakage, insider misuse of Admin QR generation. (Detailed in Project Plan risk register.)
